# 001: 書き込みに使うファームウェア

- 状態: 決定
- 日付: 2026-10-16

## 決めたいこと

Claude が作ったキーマップ([keymap-format.md](../keymap-format.md))を dotmatrix40W に書き込む方法を、ZMK と RMK + Vial のどちらにするか。

## 前提

- dotmatrix40W はワイヤレス 40%(4 行 × 12 列 + ロータリーエンコーダ)。ワイヤレス対応の自作キーボードは nRF52840 を使うことが多く、ZMK と RMK のどちらも対応している
- 使う人はコードを書かない作り手。書き込み手順は少ないほど良い
- ハッカソン期間は約1週間。確実に動く一本道を優先する

## 比較

| 観点 | ZMK | RMK + Vial |
|---|---|---|
| 言語・設定 | devicetree の `.keymap` ファイル | Rust。設定は `keyboard.toml` にまとめられる |
| 利用者の多さ、資料 | 多い。ワイヤレス自作キーボードの定番 | 少なめだが増えている |
| ビルド | GitHub Actions のテンプレートが公式にあり、UF2 をダウンロードできる | プロジェクトの雛形はあるが、ZMK ほど手順や事例がそろっていない(要確認) |
| 書き込み | UF2 ファイルをドラッグするだけ | 同じく UF2 で書き込める |
| 書き込まずに変更 | ZMK Studio。USB は対応。BLE は Linux のウェブ版かネイティブアプリのみ。エンコーダの割り当ては優先度が低く、レイヤーは事前に定義した数まで | Vial。BLE 越しのキーマップ変更に対応 |
| Claude との相性 | `.keymap` の書き方を Claude がよく知っている。生成したファイルを差分で見せやすい | `keyboard.toml` も生成しやすいが、事例が少ない |

## 推奨

**dotmatrix40W はすでに RMK で動いているため(作者に確認済み)、RMK + Vial を使う。**

ハッカソンでは次の2段構えにする。

1. **主: Vial のレイアウトファイルを書き出して読み込む。** キーマップ JSON を Vial の保存形式(`.vil`)に変換し、利用者は Vial で「読み込み」を押すだけで反映できる。ビルドも書き込みも要らないので、コードを書かない作り手に一番やさしい
2. **予備: `keyboard.toml` の初期キーマップを生成する。** Vial の変更はキーボード内に保存されるが、初期状態に戻したときの既定値を変えたい場合に、RMK のビルドと UF2 の書き込みを案内する

- 生成物がファイルなので、Claude の変更を差分で説明しやすく、評価例(docs/eval-cases.md、#5)で確かめやすい点は変わらない
- ZMK に移すとファームウェアの入れ替えが必要になり、ハッカソンの範囲を超える

## 未確定(開催期間中に検証する)

- `.vil` ファイルの形式と、エンコーダの割り当てを `.vil` で扱えるか
- Vial での変更を USB と BLE のどちらで行うか(RMK は BLE 越しのキーマップ変更に対応している)
- `keyboard.toml` のキーマップ記法と、ビルドの手順(RMK はプロジェクト雛形 `rmk-template` を用意している)
