# 002: 使う人がどこで話しかけるか

- 状態: 下書き(開催 3日目 11/4 に決める)。推奨 B の前提のうち、Skill の中でスクリプトが動くことは 2026-10-28 に確かめた(下の「試した結果」)
- 下書きの日付: 2026-10-21(決めた日に「日付」を足す)

## 決めたいこと

使う人が依頼を日本語で話しかけ、今のキーマップを渡し、新しい `.vil` を受け取る場所(受け口)をどこにするか。[plan.md](../plan.md) の 3日目午前に決め、午後はその受け口で「依頼と今のキーマップを渡し、検証を通ったキーマップ JSON を受け取る」ところまで作ります。

## 前提

- 使う人はコードを書かない作り手([project.md](../project.md))。インストールや設定の手順は少ないほど良い
- やり取りするのはファイル。今の配列は Vial で保存した `.vil` で受け取り、`scripts/from_vil.py`(Issue #21 で追加)でキーマップ JSON にする。結果は `.vil` で返し、Vial で読み込んでもらう([001-firmware.md](001-firmware.md))
- 検証と変換は Python のスクリプト(`scripts/validate_keymap.py`、`scripts/from_vil.py`、1日目に作る `.vil` の書き出し)。受け口でもこれを動かせると、Claude の出力をその場で確かめられる
- スクリプトはリポジトリの `data/rmk-keycodes.txt` と `docs/vil-format.md` の表を読む。リポジトリの外で動かすときは、これらも一緒に持っていく
- 作れるのは 9 日間。受け口に使えるのは 3日目の半日と、7日目の案内文づくりまで
- このリポジトリは公開なので、API キーなどの秘密情報を置けない

## 候補

### A. Claude Code(リポジトリを開いて話しかける)

開発で使っている形そのまま。リポジトリを手元に取り、Claude Code で「この `.vil` を Photoshop 用に」と話しかけると、スクリプトで検証して `.vil` を書き出す。

### B. Claude のプロジェクト + Skill(claude.ai のチャット)

claude.ai のプロジェクトに、手順とスクリプト(読み込むデータと表を含む)をまとめた Skill を入れておく。使う人はチャットに `.vil` を添付して話しかけ、Claude がコード実行でスクリプトを動かし、新しい `.vil` をダウンロードできる形で返す。

### C. 小さな Web ページ(Claude API を呼ぶ)

専用のページに `.vil` をドラッグして依頼を書くと、裏で Claude API を呼んで新しい `.vil` を返す。キーボードの図もページの中で見せられる。

## 比較

| 観点 | A. Claude Code | B. プロジェクト + Skill | C. Web ページ |
|---|---|---|---|
| コードを書かない作り手の始めやすさ | 低い。インストール、リポジトリの取得、ターミナルが要る | 高い。claude.ai を開き、ファイルを添付して話すだけ | 高い。ページを開くだけ |
| `.vil` の受け渡し | 手元のファイルを直接読み書きできる | 添付で渡し、ダウンロードで受け取る | ドラッグで渡し、ダウンロードで受け取る |
| 費用 | 使う人の Claude の契約 | 使う人の Claude の契約 | API の利用料を誰かが払う。公開ページなら使われた分だけかかる |
| 秘密情報 | 不要 | 不要 | API キーを置くサーバーが要る。公開リポジトリには置けない |
| スクリプトでの検証 | そのまま動く | Skill に入れたスクリプトがコード実行で動く(要確認) | ページかサーバーに移植するか、サーバーで Python を動かす |
| 9 日で作れるか | すぐ使える(今も動いている) | スクリプトが Skill の中で動けば、手順書とまとめるだけで半日で足りる見込み。動かなければ見込みが崩れる | ページ、サーバー、API キーの管理、公開まで要り、半日では足りない |
| 図や説明の見せ方 | 文字が中心。SVG はファイルで渡す | チャットの返答と、SVG などのファイル | 自由に作れる |
| 評価例での確かめやすさ | 高い。スクリプトから同じ手順を何度でも回せる | B 自体は手で回す。中身の正しさは同じ手順を A で回して確かめ、B では受け渡しの部分を数件の評価例で確かめる | API を直接呼べるので高い |

## 推奨

**B. Claude のプロジェクト + Skill を、使う人の受け口にする。開発と評価は A(Claude Code)で回す。** ただし、下の「3日目に確かめること」が通ることが条件です。

- 使う人に求めるのが「ファイルを添付して話しかける」だけで、コードを書かない作り手という前提に一番合う
- 費用は使う人自身の Claude の契約に収まり、API キーのような秘密情報を持たなくて済む
- 中身(手順とスクリプト)は A と同じものを使う。リポジトリから Skill 用のフォルダ(スクリプト、`data/`、表)をまとめる手順は `scripts/build_skill.sh` として開催前に用意した。変更のたびにそれで作り直す。評価例は A で自動で回し、B では添付とダウンロードが通るかを評価例 1〜3 で手で確かめる(7日目の試用でも確かめる)
- C は見せ方の自由度が高いが、サーバーと API キーの管理まで要り、9 日の計画に収まらない。開催後の発展として残す

## 3日目に確かめること

採用の前に、次を実際に試して確かめます。

- claude.ai のプロジェクトで、Skill に入れた Python スクリプトがコード実行で動くか
- チャットに添付した `.vil` を読み、作った `.vil` をダウンロードできる形で返せるか
- メンテナーの契約で使える機能だけで、上の流れが完結するか

### 試し方(開催前に試せる)

試験用の Skill([skill-trial/SKILL.md](../../skill-trial/SKILL.md))は、添付された `.vil` をキーマップ JSON にして検証し、JSON を返すだけのものです。キーマップは変えません。確かめるのは上の 3 点(スクリプトが動くか、添付とダウンロード、契約)だけで、評価例 1〜3 での受け渡しの確認は、3日目以降に作る本番の Skill で行います。

1. リポジトリで `scripts/build_skill.sh` を実行し、`build/dotmatrix40w-vil-trial.zip` を作る(CI と同じ中身。Skill のフォルダを読み取り専用にしてリポジトリの外で展開し、別のフォルダに出力しても動くことを `scripts/test_build_skill.sh` で確かめている)
2. claude.ai の設定でコード実行を有効にし、Skill の追加からこの zip を入れる
3. claude.ai のプロジェクトで新しいチャットを開き、[examples/dotmatrix40w-mac.vil](../../examples/dotmatrix40w-mac.vil)(または普段の `.vil`)を添付して「この .vil を読み込んで」と送る
4. 次を見る
   - Skill が使われ、スクリプトが実際に動いたか(返答に Python のバージョンと検証の結果が出る。Claude が自分で変換していないか)
   - 5 つのレイヤーの 1 行目が Vial で見ているものと合っているか
   - `keymap.json` をダウンロードできたか
5. 結果(動いた / スクリプトが動かない / ダウンロードできない)を一言、Issue か PR に書く。それをこの記録に書き込む

### 試した結果(2026-10-28)

メンテナーが、claude.ai のふつうのチャット(プロジェクトではない)で `dotmatrix40w-vil-trial` を試しました。

- **スクリプトは動いた。** 返答に Python 3.13.18 と、`validate_keymap.py` が何も出さず終了コード 0 で合格したことが出た
- **読み込みの中身は正しかった。** 5 つのレイヤーの 1 行目が [examples/dotmatrix40w-mac.json](../../examples/dotmatrix40w-mac.json) と一致した。`combo` と `settings` を読まなかったという知らせも、`.vil` の中身どおりに出た
- **`keymap.json` は、ダウンロードできるファイルとして返された**

まだ確かめていないことは、次の 2 つです。

- claude.ai のプロジェクトの中でも同じように使えるか。推奨 B はプロジェクトの形なので、3日目に本番の Skill で確かめる
- `.vil` を書き出して返す流れ。書き出しのスクリプトは開催 1日目に作る

切り替えの 1(スクリプトだけが動かない場合)は、起きないことがわかりました。

駄目だったときは、次の順で切り替えます。

1. スクリプトだけが動かない場合: B のまま、Claude が [vil-format.md](../vil-format.md) の表と規則に従って `.vil` を直接書く。その場での検証はできなくなるので、評価例は A で同じ依頼を回して確かめる
2. 添付やダウンロードもできない場合: 開催期間中のデモは A で行い、メンテナーが操作する。コードを書かない作り手が自分で使える形は C として開催後に作る。案内文(7日目)は、この制限を正直に書く
