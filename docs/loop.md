# 開発ループの詳細

## 提案(毎朝)
- 定期実行で Claude が起動し、リポジトリの状態、未完了の Issue、`docs/project.md`、`docs/ideas.md`、`docs/plan.md` を読む。
- 開催期間中は [plan.md](plan.md) のその日の行から課題を選ぶ。通る評価例が計画より 2 件以上少なければ、plan.md の「削る順番」に従う。
- 価値が高く小さい課題を最大3件選び、`proposal` ラベルの Issue を作る。
- 2026-10-27 から自走モード。Claude が自分で `approved` を付けて実装に進み、結果だけを報告する(それまでは判断カードで「採用 / 却下」を聞いていた)。

## 実装とレビュー
- 採用された Issue ごとにブランチ `issue-<番号>-<短い名前>` を作る。
- ドラフトPR → `/code-review` → 修正 → CI グリーン → Ready for review → squash マージ。
- CI の失敗やレビューコメントは PR 監視で自動対応する。
- CI の `PR rules` が、本文の `Closes #番号` が採用済み(`approved`、開いている、`rejected` なし)の Issue 1つを指すか、Ready の PR で「AIレビュー」欄の必須項目がすべてチェックされているかを確かめる。PR 側で確認を外せないよう、いつも main 側のスクリプトで動く。Issue のラベルを後から付けたときは、Actions の画面でこのジョブを再実行する(ラベルはその時点のものを読み直す)。

## 段階的な拡張
1. Issue に溜まったバグや TODO から提案の元ネタを自動で拾う。
2. 実装担当とは別の Claude がレビューする(二重チェック)。
3. ドキュメント修正などの低リスクなラベルは自動マージを許可する(2026-10-27 に、すべての PR で Claude がマージする形に広げた)。
